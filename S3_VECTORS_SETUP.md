### Using Amazon S3 Vectors as the embeddings store

This repo is configured to use Amazon S3 Vectors (preview) instead of Supabase/OpenSearch for vector storage and similarity queries.

References: [AWS announcement](https://aws.amazon.com/blogs/aws/introducing-amazon-s3-vectors-first-cloud-storage-with-native-vector-support-at-scale/)

#### Environment variables
- `S3_VECTORS_BUCKET`: Vector bucket name
- `S3_VECTORS_INDEX`: Vector index name (within the bucket)
- `S3_VECTORS_REGION`: AWS region (e.g. `us-east-1`)
- `S3_VECTORS_DIMENSION`: Embedding dimension (default 512 for CLIP)
- `S3_VECTORS_DISTANCE`: `Cosine` or `Euclidean` (default `Cosine`)
- Optional for uploader:
  - `S3_VECTORS_BATCH_SIZE` (default 500)
  - `S3_VECTORS_RATE_LIMIT_DELAY` (default 0.1)

You must also have AWS creds available in the environment (AWS SDK default resolution works in local and Lambda).

#### One-time setup
1) Create bucket and index (idempotent):
```bash
python setup_s3_vectors.py
```

#### Ingest embeddings
1) Ensure `embeddings.json` exists (generated by your pipeline or `embedding_generation/export_embeddings.py`).
2) Upload to S3 Vectors:
```bash
python upload_to_s3vectors.py
```

This stores vectors with key=`article_id` and metadata `{article_id, title, url, hash}`.

#### Query from local search utility
`search_embeddings.py` now queries S3 Vectors. Example:
```bash
python search_embeddings.py
```

#### Lambda usage
`lambda_handler.py` now queries S3 Vectors at runtime; ensure the Lambda environment includes the variables above and has IAM permission for the S3 Vectors API.

#### Notes
- The preview API is exposed via `boto3.client('s3vectors')`. Ensure an up‑to‑date `boto3`.
- For cosine distance, the code reports similarity as `1 - distance`.
